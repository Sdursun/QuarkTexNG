# Tests whose frames are known to differ from the QuarkTex 0.53 release.
# compare.py reports them as KNOWN instead of FAIL. One test per line:
# <test name> <reason>

t06_fog The 0.53 release draws fogged geometry black; the current build applies the fog colour and density as specified, and since phase 5 also without the z-buffer (first row).
a05_agl_queries The 0.53 release returns a host pointer from glGetPointerv (Amiga address plus the memory offset); the current build returns the Amiga address, which the yellow bar shows. Since phase 5 the vertex array strip with stride 0 is drawn too.
t10_zupdate Fixed in phase 5: W3D_ZBUFFERUPDATE switches depth writes. 0.53 never turned them off and switched blending instead (missing break), so the red quad hides the blue one and the green one is blended.
t11_texcolors Fixed in phase 5: W3D_SetTexEnv and W3D_SetWrapMode pass their colours as r, g, b, a; 0.53 passed r, b, g, a, so the green colours came out blue.
t12_texupdate Fixed in phase 5: W3D_UpdateTexSubImage uploads its image with srcbpr bytes per row. 0.53 uploaded the texture's original image instead and ignored calls with srcbpr != 0, so the blue and green rectangles are missing.
t03_textures Fixed in phase 5: CHUNKY textures go through their palette (first quad). 0.53 sent the indices as GL_COLOR_INDEX and ignored the palette. Fixed in phase 6: W3D_I8 textures are drawn (third row, second quad); OpenGL 1.1 does not take GL_INTENSITY as a pixel format, so the quad stayed white.
t13_texswap Fixed in phase 5: texture updates set the byte order of their format. 0.53 kept the one of the last allocation, so after an 8-bit allocation the R5G6B5 updates came out with swapped bytes (green/blue and red/white).
t14_zbuffer_io Fixed in phase 5: W3D_ReadZPixel/ReadZSpan and W3D_WriteZPixel/WriteZSpan read and write Warp3D depth values at the right place. 0.53 returned garbage (no bars) and wrote no rows.
a06_agl_pixels Fixed in phase 5: 16-bit and float pixel data (glDrawPixels, glTexSubImage2D, glReadPixels) and the glCallLists names arrive in the right byte order. 0.53 scrambled the image (top left), left out the green sub-image, drew two of the three squares, and read back garbage (missing bars).
t15_stencil Added in phase 6: the stencil buffer works (stencil functions and operations, write mask, W3D_ReadStencil*/WriteStencil*/FillStencilBuffer). 0.53 had none: every stencil call returned an error, so the blue quad covers the red diamond, the green ones show no overlap and nothing is written or read back.
t16_chroma Added in phase 6: the chroma test works (W3D_SetChromaTestBounds, W3D_CHROMATEST). 0.53 did not support it, so every texel is drawn: magenta stays in the top left quad, green and magenta in the top middle one.
t17_contexts Added in phase 6: several contexts at once; this is the first of two Warp3D contexts, red triangles without blending. In 0.53 the second context replaced the first on the host: both drew into one OpenGL context with one state, so the red triangles are blended and lie over the second context's blue, and both swaps captured frames under this name.
t17_contexts-2 Added in phase 6: the second Warp3D context of t17_contexts, in its own window with its own state (blending on). 0.53 had no separate frames for it.
t18_query Fixed in phase 6: W3D_Query and W3D_QueryDriver answer what the renderer does (red: specular, stippling, antialiasing, dithering, volume textures, culling, unknown queries; yellow: interpolated fog; white: the maximum texture sizes, also for perspective). 0.53 answered W3D_FULLY_SUPPORTED to everything else, and W3D_QueryDriver even to the maximum sizes.
t19_leaks Added in phase 6: W3D_DestroyContext frees the textures the application left (green square: ten create/destroy cycles lose less than 4 KB), and palettes are kept per context and texture. 0.53 wrote the frames of both contexts under this name (see t17_contexts), so its last one is the second window's.
t19_leaks-2 Added in phase 6: the second context of t19_leaks with its green CHUNKY texture. 0.53 had no separate frames for it.
t20_mipmap Added in phase 6: textures with a mipmap filter get mipmaps made from their image, as Warp3D makes them; the shrunk quads are an even purple. 0.53 made none, so OpenGL took the texture as incomplete and drew the quads white.
